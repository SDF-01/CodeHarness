What changed in CodeHarness

The local model is still qwen2.5-coder:7b. The harness around it is what grew: a fixed build, review, and launch procedure, plus skill, rule, and agent files it can actually read.

The short version

A turn used to end when the repo tests passed, even if the new program was broken. It can also dump tool names and token counts. A turn now names the file, asks in plain language, and only calls the result good when that program holds up.

you > build an ATM window Working Creating atm_gui.py Created atm_gui.py Needs a yes Open atm_gui.py in a window? yes? [y/n] Result The window is open.

Token counts stay off this screen. They are still available on the local page at http://127.0.0.1:8765/.

The loop

SituationWhat the harness does
A new Python file was written It parses that file. Passing the harness pytest suite is not proof the new app works.
A shell command fails The answer is blocked until a later command succeeds, or the step limit hits.
pip install tkinter Rejected before it runs. Tkinter is already part of Python.
A tkinter file exits immediately Treated as a failure. The next step is told: a window must stay open, and mainloop is required.
You ask to test the harness, or you edit a file that is not a new program check_command from codeharness.json can still run.

Each failure is stored as one lesson on the session. The next model call sees only the latest few lessons, not the whole tool dump.

Skills, rules, and agents

The file shapes match public specs. The text inside them is ours. Nothing was copied from a private prompt.

Skills

Agent Skills

One folder per skill, with SKILL.md. Required fields are name and description. The description picks the skill. The body loads only after a match, and only for two skills.

Rules

Cursor rules

description, globs, and alwaysApply. An always-on rule is in every prompt. A glob rule is included only when a file from this turn matches. AGENTS.md in the project is the same idea, capped so it cannot fill the budget.

Agents

OpenCode agents

description and mode: primary. build may create and edit files. plan may not. Type plan or build at the prompt to switch.

  • vibe-build: turn a request into one runnable file.
  • gui-app: a tkinter window, with no pip install.
  • verify: read the failure and fix that file.
  • stdlib: do not pip-install the standard library.
  • opencode: search or read a small range, then edit one exact match.

Where the files are

  • Lessons and the current agent live in .codeharness/sessions.db

See it in the terminal

A chat that is already open is still the old process. Type exit, then start a new one:

.\scripts\harness.ps1 chat
  1. Type a task at you >.
  2. Answer y or n when it asks to create a file or open a window.
  3. Type plan when you want a look with no edits, and build when you want files again.
  4. Type run to compile and launch. Type exit to stop.
